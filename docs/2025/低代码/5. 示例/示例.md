## 场景

业务需求：创建一个客户管理模块，包含客户信息维护、联系人管理、按条件筛选客户。

## Step 1：定义元数据

设计器中配置客户实体：

```xml
<entity id="crm.Customer" table="crm_customer">
  <field name="name"       type="STRING"  required="true"  />
  <field name="phone"      type="STRING"  unique="true"    />
  <field name="email"      type="STRING"                   />
  <field name="creditLimit" type="DECIMAL" default="0"     />
  <field name="status"     type="ENUM(ACTIVE,INACTIVE)" default="ACTIVE" />
  <field name="regionId"   type="REF:org.Region"           />
  <field name="createdAt"  type="DATETIME" />
</entity>

<entity id="crm.Contact" table="crm_contact">
  <field name="name"       type="STRING" required="true" />
  <field name="phone"      type="STRING" />
  <field name="customerId" type="FK:crm.Customer" required="true" />
</entity>
```

设计器保存后，元数据包以 JSON 格式写入元数据库：

```json
{
  "entityId": "crm.Customer",
  "version": "1.0.0",
  "status": "PUBLISHED",
  "schema": { /* 解析后的字段、约束、关系 */ }
}
```

## Step 2：运行时自动建表

元数据发布事件触发 DDL 生成器：

```java
@Component
public class DdlGenerator {
    @EventListener(MetadataPublishedEvent.class)
    public void handle(MetadataPublishedEvent event) {
        Metadata meta = event.getMetadata();

        // 从元数据生成 CREATE TABLE
        String ddl = buildCreateTable(meta);
        jdbcTemplate.execute(ddl);

        // 记录 schema 版本
        schemaVersionRepo.save(new SchemaVersion(meta.getEntityId(),
            meta.getVersion(), ddl));
    }

    private String buildCreateTable(Metadata meta) {
        StringBuilder sql = new StringBuilder();
        sql.append("CREATE TABLE ").append(meta.getTableName()).append(" (");
        sql.append("id BIGINT AUTO_INCREMENT PRIMARY KEY,");
        meta.getFields().forEach(field -> {
            sql.append(field.getColumnName()).append(" ")
               .append(toSqlType(field));
            if (field.isRequired()) sql.append(" NOT NULL");
            if (field.isUnique()) sql.append(" UNIQUE");
            sql.append(",");
        });
        sql.append("tenant_id VARCHAR(32) NOT NULL,");
        sql.append("INDEX idx_tenant (tenant_id)");
        sql.append(") ENGINE=InnoDB DEFAULT CHARSET=utf8mb4");
        return sql.toString();
    }
}
```

生成的 DDL 实际执行：

```sql
CREATE TABLE crm_customer (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  name        VARCHAR(200) NOT NULL,
  phone       VARCHAR(50)  UNIQUE,
  email       VARCHAR(200),
  credit_limit DECIMAL(18,2) DEFAULT 0,
  status      VARCHAR(20)  DEFAULT 'ACTIVE',
  region_id   BIGINT,
  created_at  DATETIME,
  tenant_id   VARCHAR(32) NOT NULL,
  INDEX idx_tenant (tenant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

字段映射规则：

| 元数据类型 | SQL 类型 |
|-----------|---------|
| STRING | `VARCHAR(200)` |
| DECIMAL(p,s) | `DECIMAL(p,s)` |
| ENUM | `VARCHAR(20)` + CHECK 约束 |
| DATETIME | `DATETIME` |
| REF/FK | `BIGINT` + 索引 |
| 多租户字段 | 自动追加 `tenant_id` |

## Step 3：运行时自动生成 REST API

同一元数据驱动 API 层注册标准 CRUD 路由：

```java
@Component
public class ApiAutoRegister {
    @EventListener(MetadataPublishedEvent.class)
    public void registerApis(MetadataPublishedEvent event) {
        Metadata meta = event.getMetadata();
        String path = "/api/" + meta.getEntityId().replace('.', '/');

        // 注册 CRUD 路由
        registerEndpoint(GET,    path,          new ListHandler(meta));
        registerEndpoint(GET,    path + "/{id}", new GetHandler(meta));
        registerEndpoint(POST,   path,          new CreateHandler(meta));
        registerEndpoint(PUT,    path + "/{id}", new UpdateHandler(meta));
        registerEndpoint(DELETE, path + "/{id}", new DeleteHandler(meta));
    }
}
```

启动后可直接调用：

```bash
# 创建客户
curl -X POST http://localhost:8080/api/crm/Customer \
  -H "Content-Type: application/json" \
  -d '{"name":"张三","phone":"13800138000","creditLimit":50000}'

# 查询客户列表（自动加租户过滤 + 分页）
curl "http://localhost:8080/api/crm/Customer?status=ACTIVE&page=0&size=20"
```

查询执行器自动拼接 SQL：

```java
public class QueryBuilder {
    public String buildListQuery(Metadata meta, Map<String, String> params) {
        StringBuilder sql = new StringBuilder("SELECT * FROM ")
            .append(meta.getTableName())
            .append(" WHERE tenant_id = ?");  // 自动追加租户隔离

        params.forEach((key, value) -> {
            FieldMeta field = meta.getField(key);
            if (field != null) {
                sql.append(" AND ").append(field.getColumnName()).append(" = ?");
            }
        });

        sql.append(" LIMIT ? OFFSET ?");
        return sql.toString();
    }
}
```

实际生成的 SQL：

```sql
SELECT * FROM crm_customer
WHERE tenant_id = 't001'
  AND status = 'ACTIVE'
LIMIT 20 OFFSET 0;
```

## Step 4：前端根据 UI 模板渲染

设计器拖拽生成的 UI 模板，本质是一份 JSON：

```json
{
  "pageType": "LIST",
  "entityId": "crm.Customer",
  "fields": [
    { "key": "name",       "label": "客户名称", "widget": "Input" },
    { "key": "phone",      "label": "手机号",   "widget": "Input" },
    { "key": "creditLimit","label": "额度",     "widget": "Money" },
    { "key": "status",     "label": "状态",     "widget": "Select",
      "options": [{"value":"ACTIVE","label":"启用"},{"value":"INACTIVE","label":"停用"}] }
  ],
  "searchable": ["name", "phone"],
  "actions": ["CREATE", "EXPORT"]
}
```

运行时渲染引擎执行：

```
加载 UI 模板 → 解析字段配置 → 绑定元数据验证规则 → 请求 /api/crm/Customer → 渲染列表
```

对后端而言，这就是：**前端把模板 ID + 实体 ID 发给渲染引擎，引擎自己调 API、自己拼表格，后端不用写任何页面代码。**

## Step 5：完整请求链路

```
用户操作             前端运行时                  API 网关               元数据引擎           数据库
────────             ────────                  ────────               ────────           ──────
点击"客户列表"  →  加载 UI 模板 (JSON)                                               
                    │                                            
                    ├─→  GET /api/crm/Customer?page=0&size=20
                    │                      │
                    │                      ├─→ 解析元数据 crm.Customer 的字段和表名
                    │                      │
                    │                      ├─→ 注入 tenant_id 过滤条件
                    │                      │
                    │                      ├─→ 生成 SQL + 执行
                    │                      │                     ──→ SELECT ... FROM crm_customer
                    │                      │                     ←─ 结果集
                    │                      │
                    │                      ←─ JSON 响应
                    │
                    ├─→ 按 UI 模板映射字段显示名、组件类型、格式
                    ←─ 渲染表格
```

## 总结

这个链路中后端只需要关心三件事：

| 环节 | 后端负责 |
|------|---------|
| 元数据发布 | 监听事件 → DDL 建表 → 注册 API 路由 |
| 请求处理 | 解析元数据 → 拼接 SQL（含租户/权限过滤） → 执行 → 返回 |
| 变更管理 | Schema 版本对比 → DDL差异对比迁移 |

**整个流程后端不需要写任何实体类、MAPPER、Controller、DTO。** 元数据就是实体类，DDL 自动生成替代了手动建表，通用查询引擎替代了手写 SQL。这就是低代码平台给后端带来的核心价值：**把 CRUD 层的重复劳动压缩到零，让后端聚焦在业务规则和集成逻辑上。**
